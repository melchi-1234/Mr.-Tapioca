# Mr. Tapioca 1.2.0 — "Brew Together" (build plan)

Owner greenlit a BIG meaningful update (Aug 29 2026), not a polish bump. Ship as
**1.2.0 / build 13** (current live = 1.1.1 / build 12). Theme: give the app
presence and social pull OUTSIDE the timer (where it's invisible today), and
complete the real-shop reward loop (its only true differentiator).

Grounded in a 6-agent research + codebase audit (competitors, our own gaps, VOC).
Most features are ALREADY partly built (backends switched off, art drawn + unused),
so this is largely *activation*, not new engineering. Modeled on: Flora (live
co-focus), Finch (kind pet reactions + opt-in cooperative social), Forest
(real-world payoff), Duolingo (streak-freeze framing, widget as top re-engagement),
Flipd (weekly-reset leaderboard), Cats & Soup (seasonal content calendar), Opal
(focus progress surfaced outside sessions).

## Features (ranked, biggest win first). ★ = the hard part already exists.

### 1. One-Tap Real-Shop Reward — code removal (M) ★  [ANCHOR]
Drop the 6-char cashier handoff code entirely. At the register the student sees the
shop name + exact perk instantly (from local cache, no "Getting your code…" stall)
and taps once ("Use this reward") to redeem; server-authoritative atomic row-lock
keyed to their own auth.uid() keeps it one-time even after clearing storage /
reinstalling. Card flips to a stamped "Used {time}. Enjoy" state. Surface reward
progress (e.g. 3h40m of 4h) on the drink-complete screen + settings, not only in
the Boba Map sheet.
Why: the code never worked (no live redemption ever ran, cashier page never
deployed) yet added friction at the worst moment (a line at the counter). Removing
it keeps the only load-bearing fraud protection (the row lock) and makes the real
differentiator effortless. Strongest App Store "what's new" line.
Reward-code removal specifics (files to change):
- Client delete: `redeemCode` var + `#redeemCode` UI (app.js ~6204/6243-6260/
  6357-6360/6420-6428/6472/6489/6504-6506; app.html:790; styles.css:3528-3542),
  the code-minting branch in `openRedeem()` (app.js ~6357-6442), and
  `confirmRedeem()`'s code-gated server branch (app.js ~6485-6576).
- SDK: collapse `RewardV2.openRedemption/redeemByCode/checkCode` into one
  `RewardV2.redeem(rewardId, partnerId)`.
- Server: `gen_handoff_code`, `open_redemption`'s code-minting, `redeem_by_code`,
  `check_code` (supabase-reward-v2.sql ~675-945) + the `redemption_handoffs` table
  → one `redeem_reward(reward_id, partner_id)` RPC, authenticated-only (drop the
  anon grant; no cashier device to authorize). Delete never-deployed
  `verify/index.html` cashier page + its 14 demo screenshots. Update
  reward-mock.js mirrors; rewrite reward-* tests (adversarial, cap-concurrency-sql,
  v2-client, app-authority, helper-privileges-sql, redemption). Delete the dead
  `reward-config.js` `verification` field (never read; one mode now).
- New redeem UX already ships locally on web: `confirmRedeem` local branch
  (app.js ~6579-6602) — make it server-authoritative. `RewardV2.available()/
  rewardFor()` render shop+perk with zero network wait; `rewardProgressNow()/
  RewardV2.progress()` already compute the progress numbers.
- Regression risk near-zero: no real redemption ever ran against a live DB.

### 2. Your Boba Buddy Reacts — spilled-cup moment (S) ★
When a student bails a focus session, the mascot shows a warm shocked/"aww, come
back" reaction (never shaming). The 14 `-shocked` pose PNGs already exist in
assets/poses/. `state.spillPending` is declared (app.js ~225) but only ever reset
to false (app.js ~2722), never fires anything — wire the trigger + one animation
state. Cheapest way to make 1.2.0 feel big; a reacting pet is the most-credited
retention mechanic in the genre.

### 3. Study Squad Live — brew together + real invite links (M) ★
Turn the async leaderboard into a live loop: opt-in "your friend is brewing right
now" presence (mascots focusing side by side), and fix the broken invite into a
real tappable `mrtapioca.me/squad/<code>` link a non-user can act on (shows who
invited them + one "Get the app" button). Keep the leaderboard but make it reset
WEEKLY. Backend already built + switched off: squad cloud, leaderboard, 6-char
codes, and the status pipeline (`p_status` idle/focusing/break in
squad-cloud.js ~401 RPC) all exist; only the client render was removed.
DECISIONS (owner, Aug 29): live experience is IN THE APP (iOS + web); invite link
is a web landing page that funnels to download; presence is OPT-IN (it was a
deliberate privacy non-broadcast before); collecting squad/presence/account data
means updating App Store privacy labels + privacy.html. Confirm before flipping
presence on.

### 4. Home Screen Widget (M)
WidgetKit static home-screen widget for the idle state: current streak, pearl
balance, minutes to next real reward, tap-to-start. Add as a second widget kind in
the existing FocusWidget bundle (which today ships only the Live Activity —
`FocusWidgetLiveActivity`, only an `ActivityConfiguration`, no `StaticConfiguration`
yet). Top re-engagement surface in the category (+25-34% retention in cited cases).

### 5. Weekly Wrapped share card (M) ★
"Your week in boba" recap image (hours focused, drinks brewed, streak, best day)
to post. Reuses `buildShareCard`/`buildRewardCard` canvas rendering + navigator.share
with the attributed installLink; `computeInsights` already does this-week-vs-last +
best day + streak. Feeds the owner's social/content flywheel (drives downloads).

### 6. Pomodoro auto-cycle mode (M) ★  [owner specifically likes this]
A third timer preset that auto-cycles work/break blocks (e.g. 25/5 x4) inside one
protected session. `MODES` has only custom + goal today; `startBreakOffer/startBreak`
exist between sessions — chain them automatically within one session. Most-requested
standard mechanic the app lacks.

### 7. Seasonal skin drops + more quests/badges (M)
Limited-time content calendar tied to the student year (Finals Week / Winter Break
skin available only in a window), a weekly quest tier, more badges. Shop/quest/badge
engines exist (14 skins/9 themes, `QUEST_POOL` ~11 defs app.js ~6619, 12 badges);
add art + a date-gated unlock. Rotating reason to check back.

## Economy / fairness (hold the line)
Pearls + the 240-min merchant bar come from REAL focus minutes only — never credit
streak days or quest completions toward the real U Tea/Dream Tea discount. Streak/
quest milestones pay out in pearls/cosmetics instead. Cosmetic-only, no-ads model
stays (matches genre best pattern) — expand content, not the model. Reward expiry
(partners.json null=never) and per-shop `partner_specific` offers are schema-ready
+ idle — business decisions to settle with the shops, one-line config, not eng.
Optional cleanup: the half-built 2nd squad-name-change IAP "coming soon" (app.js
~6952) — wire it or remove the placeholder.
