🧋 What is Mr. Tapioca?

A cozy, boba-themed focus & study app. You "grow" a bubble tea by staying focused — and Mr. Tapioca, a cute little tapioca pearl, makes it for you.

The core loop

It's a focus timer with a reward you can watch happen:

  • You pick a drink size (how long you want to focus).
  • You start the session — Mr. Tapioca walks over and starts mixing your drink.
  • As time passes, the cup slowly fills up with boba.
  • Finish the session → the drink is done, you earn tapioca pearls (the in-app currency), and it lands on your shelf.
  • If you bail early, you lose the drink — that little stakes keeps you honest (think Forest's dying tree).

The bigger vision

It's not just a timer. The long-term dream is:

  • Real boba-shop partnerships — finished drinks turn into real discounts at actual bubble tea shops.
  • A map of nearby boba shops so you can go redeem them.
  • Long study goals as resumable, multi-session drinks (a 6-hour "large" can be done across a few sittings).
  • And the headline feature: it actually blocks distracting apps while you study (more on that next 👇).

🎉 The big news

The main feature now works: Mr. Tapioca can really block other apps on a real iPhone during a focus session — they grey out and show a cute boba "Stay focused 🧋" screen until you're done. This is the thing that makes it a real product, not just a pretty timer.

This was the hardest part. App-blocking can only be done in a native iPhone app (a website is not allowed to touch other apps), so the project now has two halves that share the same code:

  • The web app — the whole experience (timer, games, shop, etc.), runs in any browser.
  • The native iPhone app — wraps that same web app and adds Apple's "Screen Time" blocking on top.

It's been built, signed, and tested working on a real iPhone. The Apple Developer account and the special "Family Controls" permission Apple requires are both approved. ✅

Where we are: the app is feature-rich and the blocking works. The next milestone is getting it onto TestFlight (Apple's beta-testing tool) and then the App Store. We'll keep polishing and shipping updates after launch.

🛠️ How it's built (plain English)

Good news: it's refreshingly simple under the hood. No complicated frameworks to learn.

The web app = just 3 main files

It's plain HTML, CSS, and JavaScript — no build step, no React, nothing to "compile." You edit a file, refresh the browser, and you see the change. That's it.

  • HTML = the structure (what's on the screen).
  • CSS = the look (colors, layout, animations).
  • JavaScript = the brains (the timer, games, saving your progress, etc.).

A few extra pieces

  • Service worker — lets the web app work offline and be "installed."
  • Supabase — a free cloud database that powers the live Study Squad. It's optional and turned on with a key in config.js.
  • Capacitor — the tool that wraps the web app into a real iPhone app.
  • Swift — Apple's language; we wrote a small bit of it (in native-ios/) just for the app-blocking part.

The mental model: 95% of the app is the web app. The iPhone version is that same web app in a native shell, plus a thin Swift layer for blocking. So most features & fixes are just web edits — quick and easy.

▶️ How to run & see it

The fastest way: just open the live link

The web app is hosted free on GitHub Pages. Open this on your phone or computer:

https://melchi-1234.github.io/Mr.-Tapioca/

This is the live version of the feature-work branch — whatever we've pushed shows up here a minute or two later.

To run it on your own computer (for editing)

Open the Terminal, go into the project folder, and start a tiny local server:

cd "Mr. Tapioca"
python3 -m http.server 4173

Then open http://localhost:4173 in your browser. Edit a file, refresh, see the change. 🎉

Tip: if your edits don't show up, it's the offline cache. Open the browser's dev tools → Application → clear storage / unregister the service worker, then refresh. (Or just bump the version number in sw.js.)

To run the actual iPhone app

This part needs a Mac with Xcode (Melchior's set up). The short version:

npm run ios:open    # copies the web app in & opens Xcode
# then press ▶ in Xcode to run it on a plugged-in iPhone

Full step-by-step (capabilities, Apple stuff, the tricky bits) is in SETUP_NATIVE.md.

🤝 How we work together

Most important rule: you and Melchior both commit to the same branch (feature-work). So always pull before you start and before you push, or you might overwrite each other's work.

A safe routine each time you sit down:

# before you start working
git pull --rebase origin feature-work

# ...make your changes, then...
git add -A
git commit -m "what you changed"
git pull --rebase origin feature-work   # grab anything new first
git push origin feature-work

The repo lives here: github.com/melchi-1234/Mr.-Tapioca

When something's ready for a stable public version, it gets merged from feature-work into main.
